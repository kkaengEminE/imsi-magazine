# imsi magazine CMS

imsi magazine 사이트의 글을 쓰고, 고치고, 올리고, 내리는 관리 화면이에요. 주소는 `admin.html`
(https://kkaengemine.github.io/imsi-magazine/admin.html)이에요.

글이 기사함에 들어오는 길은 두 가지예요. 둘 다 같은 기사함에 쌓여요.

- **직접 작성**: CMS의 [새 글 쓰기]에서 써요.
- **외부 API**: Hydra·Nessus 같은 다른 서비스가 받는 함수(`publish`)로 보내요 ([PUBLISH_API.md](PUBLISH_API.md)).
  초안으로 쌓을지 바로 발행할지는 보내는 쪽이 정해요.

사이트에는 **발행** 상태이고 발행 시각이 지난 글만 보여요.

## 용어

화면과 문서는 아래 다섯 개만 써요. 괄호 안은 DB 값이에요.

| 용어 | 뜻 | 사이트 |
|---|---|---|
| 초안 (`draft`) | 저장만 한 글 | 안 보임 |
| 예약 (`published` + 미래 시각) | 정한 시각에 자동 발행 | 시각 전 안 보임 |
| 발행 (`published`) | 사이트에 올라간 글 | 보임 |
| 비공개 (`pending`) | 내린 글, 또는 내보내지 않기로 한 글 | 안 보임 |
| 삭제 | 완전히 지움. 작업 기록은 남음 | 안 보임 |

글이 들어온 곳은 **직접 작성**(`origin = cms`) / **외부 API**(`origin = api`)로 표시해요.

## 권한

| 할 수 있는 일 | 에디터 | 어드민 |
|---|---|---|
| 글쓰기·이미지 넣기 | ✅ | ✅ |
| 글 수정·초안·예약·발행·비공개·삭제 | 자기 글만 | 모든 글 |
| 외부 API로 들어온 글 | 담당자로 지정된 글만 | ✅ |
| 다른 사람 글 보기 | ❌ (일정표에 '다른 글 예약'으로만) | ✅ |
| 계정 관리·설정·작업 기록 | ❌ | ✅ |
| 내 정보 (이름·비밀번호) | ✅ | ✅ |

권한은 DB 규칙(RLS)으로 막아요. 화면은 역할에 맞게 메뉴와 버튼만 숨겨요.
사용 중인 어드민은 항상 한 명 이상 있어야 해요.

## 화면

| 화면 | 주소 | 누가 | 하는 일 |
|---|---|---|---|
| 로그인 | | 모두 | 이메일·비밀번호 |
| 기사 | `#/` | 모두 | 상태 탭(전체·초안·예약·발행·비공개), 제목 검색, 담당자·들어온 곳 필터(어드민), 쪽 넘기기 |
| 새 글 쓰기 / 글 수정 | `#/new`, `#/edit/:id` | 모두 | 제목·요약·카테고리·기자명·태그·대표 이미지(올리기)·본문 편집기(이미지 넣기, HTML 보기)·출처·편집 메모·담당자(어드민)·발행 시각. 버튼: 초안 저장·예약·지금 발행·변경 저장·비공개로·삭제 |
| 발행 일정 | `#/schedule` | 모두 | 7일 단위 발행 시간표 |
| 계정 관리 | `#/accounts` | 어드민 | 계정 추가·이름·역할 수정·비밀번호 초기화·사용 중지·삭제(글 넘겨받을 사람 지정) |
| 설정 | `#/settings` | 어드민 | 카테고리, 발행 시간대, 메인 고정 기사, 외부 API(받는 주소, 키 설정 여부, 들어온 글 기본 담당자) |
| 작업 기록 | `#/log` | 어드민 | 누가 언제 어떤 글을 작성·수정·상태 변경·담당자 변경·삭제했는지 |
| 내 정보 | `#/me` | 모두 | 이름, 비밀번호 변경 |
| 도움말 | `#/help` | 모두 | 용어·흐름·권한 |

CMS에서 한 번이라도 고친 외부 API 글과 CMS에서 직접 쓴 글은, 외부 API가 같은 번호로 다시 보내도
덮어쓰지 않아요(`409`). 외부 API로는 직접 쓴 글을 지울 수도 없어요.

## 구성

| 구분 | 파일 |
|---|---|
| 화면 | `admin.html`, `assets/admin.css`, `assets/cms/*.js` (화면별) |
| DB | `supabase/schema.sql` → `migrations/002_cms.sql` → `migrations/003_roles_authoring.sql` |
| 받는 함수 | `supabase/functions/publish/` |
| 계정 관리 함수 | `supabase/functions/admin-users/` (관리자 키가 필요한 계정 작업) |

DB 표: `articles`(기사), `editors`(CMS 계정·역할), `article_events`(작업 기록, 트리거가 남김),
`site_settings`(설정, 사이트도 공개로 읽음 — 비밀값 넣지 않음). 이미지는 Storage `article-images`(공개 읽기).

## 처음 설정 순서

1. SQL Editor에서 `migrations/003_roles_authoring.sql` 실행
   (`admin@im.si` 계정이 있으면 어드민으로 지정됨)
2. Edge Functions에 새 함수 `admin-users` 만들기: `index.ts`, `logic.ts` 두 파일. Verify JWT는 켠 채로 둬요.
3. 기존 함수 `publish` 다시 배포: `index.ts`, `logic.ts` 두 파일 (Verify JWT 끔, 그대로)
4. `admin.html`에 어드민으로 로그인 → 계정 관리에서 에디터 추가

1번보다 3번을 먼저 하면 받는 함수가 새 칸을 못 찾아 실패하니 순서를 지켜요.
